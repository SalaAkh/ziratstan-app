# План миграции данных Ziratstan.kz на сервера РК (Enterprise Compliance)

## Концепция локализации СУБД
В соответствии с Законом РК «О персональных данных и их защите», сбор, обработка и хранение персональных данных граждан Республики Казахстан должны осуществляться на серверах, физически расположенных на территории РК.

Для Ziratstan.kz мы выбираем гибридную архитектуру или полный перенос БД:
1. **Frontend (Hosting):** Firebase Hosting (CDN кэшируется глобально, это допустимо).
2. **Backend/DB:** Self-hosted Supabase на локальных мощностях (VPS) в дата-центрах РК, например:
   - **PS.kz** (Алматы)
   - **Yandex Cloud KZ** (Караганда)

## Технические шаги миграции

### Шаг 1: Подготовка инфраструктуры (PS.kz / Yandex Cloud KZ)
- Аренда виртуального сервера (VPS): минимум 4 CPU, 8 GB RAM, 100 GB NVMe.
- Установка Docker и Docker Compose.
- Настройка Firewall (UFW) для закрытия портов БД снаружи (оставляем только 443 для API и 80 для редиректов).

### Шаг 2: Развертывание локального Supabase (Self-Hosting)
- Скачивание официального репозитория `supabase/supabase`
- Настройка локального `.env` файла (генерация новых JWT Secret, Anon Key, Service Role Key).
- Запуск `docker-compose up -d`.
- Установка SSL-сертификата (через Nginx Reverse Proxy и Let's Encrypt) для безопасного подключения.

### Шаг 3: Экспорт и импорт данных (Downtime: ~30-60 минут)
1. Остановка записи в текущей Cloud Supabase (включение Maintenance Mode).
2. Дамп схемы базы данных и ролей (RLS).
3. Дамп пользовательских данных с использованием `pg_dump`.
4. Восстановление данных на локальном Supabase сервере в РК (`psql -h localhost -U postgres -f dump.sql`).
5. Перенос файлов из Supabase Storage (бакеты с фотографиями и документами) при помощи AWS S3 CLI (`aws s3 sync`).

### Шаг 4: Переключение Endpoint'ов
- В файле `src/js/config.js` смена ключей и URL на локальные:
  ```js
  // Переключение в config.js
  const IS_KZ_LOCALIZED = true; 
  ```
- В `functions/.env` замена `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`.
- Деплой обновленного клиента и Firebase Functions (`firebase deploy`).

### Шаг 5: Аудит и Compliance
- Внедрение SQL Views с маскированными данными для аналитики (email и телефоны закрываются маской).
- Тестирование авторизации и отработки RLS политик на новом сервере.
- Размещение плашки "Данные защищены юрисдикцией РК" в UI для повышения доверия (выполнено).

## Итог для Бизнеса (LTV & Scale)
- Полное легальное соответствие требованиям регуляторов (КНБ, МЦРИАП).
- Готовность работы с B2B-клиентами, мечетями и государственными структурами, которые требуют строгий compliance.
- Снижение ping'а для пользователей из Казахстана (ускорение загрузки профилей).
